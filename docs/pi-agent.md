# Pi 第一阶段：报告查询

已接通：Pi 模型 → `query_report_status` 工具 → 现有业务 API → CloudBase。提供独立 Pi 聊天页面和命令行，支持进程内多轮上下文。知识检索、独立规则工具和持久会话尚未接入。原 Dify H5 页面继续保留为对照。

使用官方 Pi 组件 `@earendil-works/pi-agent-core` 和 `@earendil-works/pi-ai`，锁定 1.4.0。第一版模型入口使用 OpenRouter，后续可替换供应商。

## 启动

先安装 Node.js 22.19+，在项目文件夹执行 `npm ci`。在已有 `.env` 中补充以下三项，不要覆盖原有配置：

```dotenv
PI_MODEL_API_KEY=你的OpenRouter密钥
PI_MODEL=deepseek/deepseek-chat
PI_BUSINESS_BASE_URL=http://127.0.0.1:3000
```

模型 ID 可更换为 Pi 当前模型目录中支持工具调用的 OpenRouter 模型。模型请求会将问题、会话上下文和查询结果发送给模型供应商，请使用项目虚构数据验证。密钥只放在本机 `.env`，不要发到聊天或提交仓库。Dify 应用密钥不能替代模型密钥。

仍需已有的 `CLOUDBASE_BASE_URL` 和 `CLOUDBASE_TOKEN` 配置。在项目文件夹打开终端，运行：

```sh
npm run agent:web
```

浏览器打开终端输出的地址，默认 http://127.0.0.1:5180 。这是 Pi 页面；`npm run preview` 启动的旧页面仍连接 Dify。Pi 页面显示真实工具执行进度，提供“新对话”按钮；会话在内存保留，闲置 30 分钟过期，最多 20 轮，服务重启后清除。只监听本机地址。

本机业务 API 默认由 Pi 自动启动，使用临时端口，不需要再运行 `npm start`。这避免依赖可能未启动或被占用的 3000 端口。若要调用单独运行的业务服务，设置 `PI_BUSINESS_MODE=http`，并配置 `PI_BUSINESS_BASE_URL`；远程 HTTPS 地址会直接使用，不自动启动本机接口。可用 `PI_WEB_PORT` 修改页面端口。

命令行交互入口：

```sh
npm run agent
```

也可以单次提问：

```sh
npm run agent -- "察尔汗一号盐湖矿山2024年储量年报提交了吗？"
```

交互模式输入 `/exit` 退出。重启后清除会话；当前没有用户鉴权或聊天历史存储，不作为公开服务部署。

## 验收

1. 问“察尔汗一号盐湖矿山2024年储量年报提交了吗？”：应调用业务工具，按真实返回记录回答。
2. 问“那2030年的呢？”：应沿用明确的矿山和报告类型；无记录时说明无法判断，不能说未提交。
3. 新会话问“储量年报交了吗？”：应补问矿山和年度，不自行猜测。
4. 页面应显示工具的“进行中 / 已完成 / 未成功”，新对话应清除旧条件。接口失败不能被解释成报告未提交。

缺条件追问、上下文理解和自然语言回答需要真实模型逐项验收。提示词约束不能替代这些实测。

```sh
npm run test:agent
```

自动测试使用 Pi 官方模拟模型与模拟业务响应，覆盖 Agent 循环、工具入参、无记录保留、失败处理、调用上限，以及网页会话隔离、过期、重置和工具事件。`npm test` 同时执行旧功能回归。

2026-10-28 已使用真实 OpenRouter 模型和 CloudBase 数据完成“2024 年报告 → 追问 2030 年”的命令行联调；独立网页接口的“缺年度补问 → 补充2024年 → 追问2030年”三轮真实验收也通过。浏览器视觉与用户操作仍需实测。真实联调命令会产生少量模型费用，不包含在自动测试中：

```sh
npm run agent:check
```

启动 Pi 页面后，可运行 `node agent/check-web.mjs` 验证真实网页接口的补问、补齐条件查询、连续追问。该命令不代替浏览器视觉验收。
