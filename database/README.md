# 数据库规划

本阶段只记录设计方向，不创建数据库、表或数据。

后续使用 SQLite，建议从以下三类记录开始：

| 记录 | 作用 | 计划包含的信息 |
| --- | --- | --- |
| 矿山 | 确定查询对象 | 矿山 ID、虚构名称 |
| 年度应交资料 | 定义该矿山该年度的应交清单 | 资料项 ID、矿山 ID、年份、资料名称 |
| 提交记录 | 标记应交项是否已提交 | 提交记录 ID、应交资料项 ID、提交时间 |

应交资料按矿山、年份确定；提交记录关联对应应交项。同一应交项即使有多条提交记录，也只计为已提交一项。缺失清单为不存在提交记录的应交项集合。尚未配置年度应交清单时返回“无清单，无法判断”，不返回“齐全”。

实现时添加建表脚本与独立的虚构数据初始化脚本，约束资料项唯一性及记录关联关系。所有名称、资料清单和提交记录均为课程演示虚构内容，不代表真实监管要求。

本地运行时数据库计划位于 `instance/`，该目录不提交到 Git。公网部署时使用持久化目录；数据库路径通过后端配置指定。建表与演示数据脚本纳入 Git，数据库文件不纳入 Git。
