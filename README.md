# 矿业智询（Mining AI Assistant）

面向矿业监管人员的 AI 智能查询助手 MVP，用于 AI 产品课程作业。

## 当前进度

当前已完成 [移动端 H5 智能助手前端](app/README.md)：在仓库根目录执行 `node app/preview.mjs`，打开 http://localhost:5173 即可演示。包含三个可点击问题、聊天气泡、底部输入框和查询加载状态；使用独立前端 Mock 答复，尚未接入 Dify。原生 HTML/CSS/JavaScript，无需依赖安装或打包构建。

另有独立的 [报告状态 Mock API](mock-api/README.md)，执行 `node mock-api/server.js` 即可本地运行。它使用 JSON 虚构数据，尚未与本次前端连接。Flask 后端、数据库和真实大模型调用尚未实现，也尚未部署。仓库不包含真实矿山数据、真实业务接口、密码或 API Key。下方保留早期架构规划，当前前端运行说明以 `app/README.md` 为准。

## 产品定位与核心场景

帮助监管人员通过自然语言查询某矿山某年度的监管资料提交情况，减少逐项查表的操作。

演示问题：“演示矿山 A（虚构）2026 年资料齐全吗？”

后续系统应识别矿山和年份，查询数据库中的应交资料清单及提交记录，返回：

- 应提交的资料项数；
- 已提交的资料项数；
- 缺失资料名称；
- 根据数据库记录得出的齐全或不齐全结论。

“齐全”仅表示应交清单中的各项均存在提交记录，不表示资料内容真实、有效或已通过审批。所有演示名称和记录均使用明确标注的虚构数据。

## MVP 范围（待实现）

| 能力 | 最小实现范围 |
| --- | --- |
| 可交互前端 | 单页面提问输入框、提交按钮、加载状态、结果与错误提示 |
| 后端 | 接收问题、校验参数、查询数据库、返回结构化结果 |
| 真实大模型 API | 由后端调用，将问题解析为矿山名称和年份；本阶段不接入 |
| 数据库 | 保存虚构矿山、年度应交清单及提交记录 |
| 公网访问 | 部署一个同时提供页面和查询接口的服务 |
| Git 版本管理 | 按开发阶段审查变更并提交 |

处理流程：用户提问 → 后端调用模型提取矿山与年份 → 后端校验 → 参数化数据库查询 → 程序计算数量及缺项 → 前端展示结果。

模型负责理解问题，数量、缺项和齐全结论以数据库查询及程序计算为准。模型不直接生成或执行 SQL。矿山未找到、名称不唯一、年份缺失或年度应交清单未配置时，应明确提示，不能把“查不到”当作“资料齐全”。重复提交同一资料项只计一项，非应交资料不计入已交数量。

## 技术方案

- 前端：原生 HTML、CSS、JavaScript，暂不引入前端框架或构建工具。
- 后端：Python + Flask，页面与接口由同一服务提供，减少部署步骤。
- 数据库：SQLite，通过 Python 内置的 `sqlite3` 访问，适合课程演示的小规模数据。
- 模型：后续选择支持结构化输出的大模型 API，供应商与模型待定；密钥仅在后端读取。
- 部署：后续选择支持 Python 和持久化磁盘的平台，部署单实例 Flask 服务，使用生产 WSGI 服务器；SQLite 文件放在持久化目录。上线前验证重启后数据仍保留，不使用 Flask 开发服务器对公网提供服务。

暂不引入微服务、消息队列或复杂 ORM。RAG 存储与 Dify 编排方案待评估。依赖及具体版本在开始编码时确定并记录，本次不安装依赖。

技术参考：[Flask 项目结构](https://flask.palletsprojects.com/en/stable/tutorial/layout/)、[SQLite 使用说明](https://flask.palletsprojects.com/en/stable/tutorial/database/)、[Flask 生产部署](https://flask.palletsprojects.com/en/stable/deploying/)。

## 数据与配置约定

- 仅使用自行编写并明确标注的虚构演示数据，不放入真实项目导出文件。
- 后续环境变量模板仅列出变量名与空值，不填入真实凭据。
- 本地配置放在被忽略的 `.env` 中；线上凭据通过平台环境变量配置，不能放进前端代码。
- 数据库文件不提交；后续提交建表与虚构数据脚本，以便重建演示环境。
- 提交前检查 `git status` 和 `git diff`，确认只包含本阶段预期变更。

## 后续开发计划

1. **最小应用骨架**：添加依赖清单和 Flask 入口，实现可打开的页面及健康检查接口，补充本地启动步骤。
2. **数据库与确定性查询**：建立表结构和虚构数据，先用明确的矿山、年份参数完成资料统计；验证缺项、重复提交、矿山不存在和清单未配置等情况。
3. **前后端联通**：实现输入、提交、加载、结果展示与错误提示，验证一次完整查询流程。
4. **真实模型接入**：通过后端调用真实 API，解析自然语言；校验模型输出，处理超时和解析失败，避免模型编造查询结果。
5. **公网演示**：添加部署配置、持久化数据库、后端环境变量、调用限额与超时控制，验证公网查询及重启后数据保留，并在 README 中记录访问地址。
6. **课程验收**：整理演示步骤、系统说明和验证记录，确认前端、后端、真实模型、数据库、公网访问和 Git 历史均可展示。
